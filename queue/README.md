# DeepSpeak — System V IPC Messenger

Десктопный и консольный мессенджер **DeepSpeak**, построенный поверх очередей сообщений System V (`sys/msg.h`), разделяемой памяти System V (`sys/shm.h`) для передачи файлов и фото, потоков POSIX (`pthread`), локальной базы данных **SQLite3** и графического интерфейса **GTK 3**.

## Состав

- **`protocol.h`** — общий бинарный протокол и общие `static inline`-хелперы:
  - ключ очереди (`ftok("/tmp", 'Q')`), lock-файл арбитра (`/tmp/queue_arbiter.lock`), пути к БД (`users.db`) и папкам вложений (`uploads/`, `downloads/`), лимит файла (`MAX_FILE_SIZE` — 8 МБ);
  - структура `struct qmsg` с таймстемпами и коды команд (`CMD_REGISTER`, `CMD_LOGIN`, `CMD_SET_THEME`, `CMD_CHAT`, `CMD_HISTORY`, `CMD_HISTORY_ITEM`, `CMD_DELETE_CHAT`, `CMD_DELETE_ROOM`, `CMD_MARK_READ`, `CMD_ACK`, `CMD_WHO`, `CMD_ROOM_*`, `CMD_FILE_SEND`, `CMD_FILE_GET`);
  - безопасная UTF-8 обрезка строк (`copy_utf8_safe`), форматирование времени, валидация идентификаторов и имён файлов, парсинг маркеров `[[FILE:...]]` и передача файлов через Shared Memory (`shm_alloc_from_file`, `shm_save_to_file`).
- **`db.h` / `db.c`** — модуль хранения на **SQLite3** (`users.db`, исключён из Git через `.gitignore`):
  - таблица `users`: регистрация и аутентификация с 256-битным солёным хэшированием паролей (соль из `/dev/urandom`, сравнение за константное время), сохранение выбранной темы (`theme_id`) и автозаполнение стартовыми аккаунтами при первом запуске (`dmitry` / `123456`, `alice` / `alice123`, `bob` / `bob123`);
  - зарезервированный отладочный префикс `user*` (без учёта регистра): регистрация запрещена, вход разрешён без записи в БД по отладочному паролю (`debug123` или из переменной окружения `QUEUE_DEBUG_PASS`), переписки и темы отладочных аккаунтов в базе не сохраняются;
  - таблицы `messages`, `room_messages`, `room_members`, `room_cleared`, `room_read`: хранение истории личных чатов, комнат и вложений (`[[FILE:...]]`), автовосстановление участия в комнатах при входе, удаление переписок со стороны пользователя (с физической очисткой в БД, когда историю удалили обе стороны или все участники комнаты) и постоянный учёт статуса прочтения (`is_read`, `last_read_id`) с автоматической миграцией схемы.
- **`extraq.c`** — процесс-арбитр и многопоточный консольный клиент (`pthread`):
  - защита от запуска второго экземпляра арбитра через `flock` (`/tmp/queue_arbiter.lock`);
  - авторизация через SQLite3 (`CMD_REGISTER`, `CMD_LOGIN`), отладочный режим `[DEBUG]` для `user*` и маршрутизация личных сообщений через арбитра с сохранением в БД;
  - передача файлов (до 8 МБ) в лички и комнаты через **System V Shared Memory** (`CMD_FILE_SEND`, `CMD_FILE_GET`) с хранением в `uploads/` и гарантированным освобождением сегментов (`IPC_RMID`);
  - контроль активности (`heartbeat` каждые 4 с, таймаут 10 с), список пользователей онлайн (`CMD_WHO`), многопользовательские комнаты и синхронизация статусов прочтения (`CMD_MARK_READ` и `CMD_ACK`, включая массовое подтверждение `msg_id = 0` для офлайн-сообщений);
  - офлайн-буфер (`chat_backlog.dat`, TTL 60 с) для отладочных аккаунтов;
  - цветной CLI-интерфейс с таймстемпами (`[HH:MM:SS]` и `[DD.MM HH:MM]` для прошлых дней).
- **`gui_client.c`** — десктопный клиент **DeepSpeak** на **GTK 3** с экраном авторизации, меню `☰`, инлайн-превью фотографий, живым переключением тем, масштабированием интерфейса и полной совместимостью с консольным клиентом `./extraq client`.
- **`2_Q.c`** — базовый парный чат между двумя терминалами по числовым `mtype` через `fork()`.

## Зависимости

Для сборки арбитра и графического клиента в Ubuntu требуются SQLite3, GTK 3 и `pkg-config`:

```bash
sudo apt update
sudo apt install libsqlite3-dev libgtk-3-dev pkg-config
```

## Сборка

```bash
make          # собрать всё (2_Q, extraq, gui_client)
make extraq   # собрать только арбитра и консольный клиент (SQLite3 + pthread)
make gui      # собрать только графический клиент (GTK 3)
make clean    # удалить бинарники
```

## Запуск

### Арбитр (обязательно запускается первым)

```bash
./extraq arbiter
```

При необходимости можно переопределить отладочный пароль для аккаунтов `user*`:

```bash
QUEUE_DEBUG_PASS=mysecret ./extraq arbiter
```

Повторный запуск арбитра блокируется через `flock`. Остановка (`Ctrl+C`) сохраняет бэклог, корректно закрывает `users.db`, удаляет очередь из ядра и снимает lock-файл.

### Графический клиент (GTK 3)

Запускается из отдельного терминала (флаг `&` открывает окно в фоне, не блокируя консоль):

```bash
./gui_client &
./gui_client &
```

- **Экран авторизации** — стартовая карточка входа и регистрации (`Username`, скрытое поле `Password`, кнопки `Log In` и `Register`, отображение ошибок и подсказка по отладочным аккаунтам `user*`).
- **Меню `☰` в верхней панели (`GtkPopover`)** — компактное выпадающее меню:
  - информация об аккаунте (`username`, пометка `[DEBUG]`, `ID` сессии);
  - выбор масштаба (`Auto` с динамическим изменением шрифта и ширины сайдбара при ресайзе/развороте окна на весь экран, либо фиксированный `10pt–18pt`);
  - 5 тёмных тем оформления на лету (`Catppuccin Mocha`, `Nord Dark`, `Gruvbox Dark`, `Tokyo Night`, `Cyber Dark`) с сохранением выбранной темы в `users.db`;
  - кнопка `Logout`.
- **Шапка активного чата и меню `⋮`** — отображение статуса собеседника (`online`/`offline`) или числа участников комнаты и кнопка `⋮` с действиями (`Delete Chat` для лички, `Leave Room` и `Delete Room` для комнаты) с модальным диалогом подтверждения перед удалением.
- **Нижняя панель с контекстной кнопкой (`+` / `📎`)**:
  - при открытом `★ System` в левом нижнем углу отображается кнопка **`+`**, открывающая диалог начала нового чата или входа в `#room`;
  - при открытом чате или комнате на этом месте появляется скрепка **`📎`** со всплывающим меню **`📷 Photo`** (выбор изображений с фильтром форматов) и **`📄 File`** (любой файл до 8 МБ).
- **Файлы и инлайн-превью фотографий** — изображения (`.png`, `.jpg`, `.jpeg`, `.gif`, `.bmp`, `.webp`) декодируются из Shared Memory через `GdkPixbufLoader`, масштабируются (до `260×220`), кэшируются и отображаются прямо в ленте чата; остальные файлы рендерятся как кнопки `File: <имя> (<размер>)`. Клик по фото или файлу открывает диалог сохранения оригинала.
- **Правая панель `Users | Rooms`** — список пользователей (`●` онлайн / `○` офлайн) и активных комнат (`#room (N)` / `+ #room (N)` для быстрого входа) с постоянными счётчиками непрочитанных, которые сохраняются после `Logout` и перезапуска.
- **Статусы прочтения (в стиле Telegram)** — `✓` при отправке, переход в `✓✓` при прочтении собеседником (включая массовое обновление всех висящих `✓` → `✓✓`, когда офлайн-получатель возвращается в сеть и открывает диалог).

### Консольный клиент (терминал)

Может работать параллельно с `gui_client` через одного арбитра:

```bash
./extraq client
```

Команды:
- `#<ник> <пароль>` — регистрация нового аккаунта в `users.db`;
- `@<ник> <пароль>` — вход в существующий или отладочный (`user*`) аккаунт;
- `<ник>#<текст>` — отправка личного сообщения;
- `/join <комната>` — создать или войти в комнату;
- `/leave <комната>` — выйти из комнаты;
- `/rooms` — список активных комнат (`*` — комнаты, в которых вы состоите);
- `/r <комната> <текст>` — отправить сообщение в комнату;
- `/history [ник|#комната]` — загрузить историю переписки из БД;
- `/delchat <ник|#комната>` — удалить историю чата или комнаты для себя;
- `/sendfile <ник|#комната> <путь>` — отправить файл через Shared Memory (до 8 МБ);
- `/getfile <file_id> [путь]` — скачать файл из `uploads/` (по умолчанию в `downloads/`);
- `?` или `/who` — список пользователей онлайн;
- `##` — выход из аккаунта;
- `Ctrl+D` — завершение клиента.

### Базовый чат `2_Q`

Запускать из директории с `2_Q.c`:

```bash
./2_Q 1 2   # терминал 1
./2_Q 2 1   # терминал 2
```
